# نظام اليوسف — تطبيق سطح مكتب (Tauri + SQLite)

هذا تحديث للنسخة اللي بنيتها وثبّتها بالفعل — التطبيق نفسه (`dist/index.html`)
لسه هو هو، بس طريقة حفظ البيانات اتغيّرت من ملف JSON بسيط لقاعدة بيانات
**SQLite حقيقية** (`data.db`)، عشان الحماية من فقد/تلف البيانات مع كبر
حجمها مع الوقت.

## ليه اتغيّرت الطريقة؟
ملف JSON كان بيتكتب بالكامل من الصفر في كل حفظة — لو حصل قطع كهرباء أو
تعليق للجهاز بالظبط في نفس اللحظة، الملف ممكن يتلخبط بالكامل. قاعدة
البيانات بتضمن إن كل حفظة إما تتم **بالكامل** أو **محصلش خالص** (لا يوجد
احتمال ثالث نص مكتوب) — وده الفرق الجوهري.

## إيه اللي اتغيّر بالظبط في الكود؟
**التطبيق نفسه، الشاشات، والحسابات (الضمانات، الخصومات، المستخلصات...)
متغيّرش ولا سطر واحد فيهم.** اللي اتغيّر بس هو الطبقة اللي بتحفظ/تجيب
البيانات:

1. تصميم قاعدة بيانات كاملة (18 جدول) بيغطي كل كيان في البرنامج — موجود في
   `src-tauri/migrations/001_initial.sql`، وبيتفعّل أوتوماتيك أول ما
   البرنامج يفتح.
2. دالتَي `save()` و `load()` بقوا بيتعاملوا مع قاعدة البيانات دي بدل ملف
   JSON، عن طريق الإضافة الرسمية من فريق Tauri نفسه (`tauri-plugin-sql`).
3. **نقل تلقائي لمرة واحدة**: أول ما تفتح النسخة الجديدة دي، البرنامج
   بيكتشف لوحده وجود بياناتك القديمة (`data.json` من النسخة السابقة)،
   وينقلها لقاعدة البيانات الجديدة تلقائيًا — وبيتأكد إن إجمالي قيم
   العقود والمستخلصات **متطابق قبل وبعد النقل بالظبط** قبل ما يعتبر
   العملية ناجحة. الملف القديم `data.json` بيفضل موجود على الجهاز كنسخة
   احتياطية إضافية، مش بيتمسح.

## ✅ اللي اتأكّد منه فعليًا (مش مجرد كلام)
بعكس التحديث اللي فات، الجزء الأخطر هنا — تصميم الجداول ومنطق النقل بين
الشكل القديم والجديد — **اتفحص فعليًا بقاعدة بيانات SQLite حقيقية** في
بيئة التطوير (مش مجرد كود متوقع إنه يشتغل):
- كل الجداول اتعمل فعليًا وقُبلت من غير أخطاء.
- قيود الربط بين الجداول (Foreign Keys) اتأكد إنها بترفض أي بيانات
  متناقضة، وإنها بتنضّف المراجع المعلّقة تلقائيًا عند الحذف.
- عملية "حفظ → قراءة" الكاملة لكل كيان (عملاء، عقود، بنود كميات، أوامر
  إسناد، مستخلصات، باطن، موردين...) اتعملها اختبار شامل يتأكد إن كل رقم
  وكل حقل بيرجع **مطابق تمامًا** بعد الحفظ والقراءة، لعينة بيانات واقعية
  فيها كل الحالات الخاصة (حقول فاضية، عناصر بدون ربط، عناصر متداخلة).
- ملفات الاختبار دي موجودة في مجلد `dev-tests/` لو حبيت تراجعها أو تعيد
  تشغيلها بنفسك.

**الجزء اللي لسه مش مُتأكَّد منه فعليًا** هو نفسه زي المرة اللي فاتت: كود
الـ Rust اللي بيوصّل التطبيق بقاعدة البيانات (`src-tauri/`) — لأن بيئة
التطوير معندهاش نسخة Rust حديثة كفاية تجرّب بيها. أول اختبار حقيقي لده
هيكون على GitHub Actions زي المرة اللي فاتت.

## طريقة الحصول على installer الجديد
نفس الخطوات بالظبط اللي عملتها المرة اللي فاتت:

1. حدّث نفس المستودع بتاعك على GitHub بالملفات الجديدة (استبدل القديمة).
2. تأكد إن `.github/workflows/build-windows.yml` اترفع صح (زي ما حصل
   المرة اللي فاتت).
3. روح تبويب **Actions** — هيشتغل تلقائي.
4. بعد 10-15 دقيقة، نزّل `.msi`/`.exe` من **Artifacts**.
5. ثبّته **فوق النسخة القديمة** المثبّتة عندك (زي أي تحديث برنامج عادي)
   — بياناتك هتتنقل تلقائيًا أول ما يفتح، زي ما اتشرح فوق.

## مكان حفظ البيانات بعد التحديث
`%APPDATA%\com.alyousef.erp\data.db` — ده الملف الرئيسي الجديد.
`%APPDATA%\com.alyousef.erp\data.json` — النسخة القديمة، هتفضل موجودة
كنسخة احتياطية إضافية.

زرار "تصدير نسخة احتياطية (JSON)" جوه البرنامج لسه شغّال بنفس الطريقة
القديمة تمامًا، تقدر تستخدمه وقت ما حبيت.

## الأيقونة
لسه بسيطة مؤقتة بألوان البرنامج — استبدلها بلوجو الشركة في
`src-tauri/icons/` وقت ما حبيت.

## لو حابب تبني محليًا على جهاز Windows عندك (اختياري)
1. ثبّت [Rust](https://www.rust-lang.org/tools/install) و
   [Node.js](https://nodejs.org).
2. من داخل المشروع: `cargo install tauri-cli --version "^2.0.0"`
3. `cargo tauri build`
4. الناتج في: `src-tauri/target/release/bundle/msi/` أو `.../bundle/nsis/`
